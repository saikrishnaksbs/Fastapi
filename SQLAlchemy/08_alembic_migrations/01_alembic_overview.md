# Database Migrations with Alembic & SQLAlchemy 2.0

Alembic is the official database migration tool for SQLAlchemy. It tracks database schema changes over time and applies versioned migration scripts.

---

## 🛠️ Step-by-Step Alembic Workflow

### 1. Installation
Install Alembic alongside your database driver:
```bash
pip install alembic
```

---

### 2. Initialize Alembic
In your project directory, run:
```bash
alembic init alembic
```
This generates:
* `alembic.ini`: Configuration file containing database URL settings.
* `alembic/`: Directory containing migration environment scripts and revision templates.
  * `alembic/env.py`: The Python script executed whenever Alembic runs migrations.
  * `alembic/versions/`: Directory storing generated migration revision files.

---

### 3. Configure `env.py` for SQLAlchemy 2.0
Open `alembic/env.py` and connect it to your SQLAlchemy `DeclarativeBase` metadata:

```python
# Import your Base metadata from your application models
from my_app.models import Base

# Set target_metadata so Alembic can detect model changes
target_metadata = Base.metadata
```

To dynamically read the DB connection string from environment variables or settings:
```python
from my_app.config import settings

config.set_main_option("sqlalchemy.url", settings.DATABASE_URL)
```

---

### 4. Generate Autogenerated Migrations
Whenever you add, modify, or delete a model or column in Python, generate a migration revision script:

```bash
alembic revision --autogenerate -m "Add users and posts tables"
```

Alembic compares your `Base.metadata` models against the actual database schema and creates a new script under `alembic/versions/`.

---

### 5. Review & Apply Migrations

Always inspect the generated file in `alembic/versions/` before running it!

#### Apply migrations (upgrade DB to latest version):
```bash
alembic upgrade head
```

#### Rollback migrations (downgrade DB by 1 version):
```bash
alembic downgrade -1
```

#### View migration history:
```bash
alembic history --verbose
```

---

## 💡 Best Practices with SQLAlchemy 2.0

1. **Always Review Autogenerated Code**: Alembic detects table creations, column additions, and type changes well, but may miss table renames or custom DB constraints unless configured.
2. **Include Migration Checks in CI/CD**: Run `alembic check` in your testing pipeline to ensure developers haven't committed model changes without creating a corresponding migration.
3. **Use Async Engine in `env.py`**: If your app uses async SQLAlchemy (`AsyncEngine`), configure `env.py` to use `asyncio` and `run_sync()` for running migrations.
